1. WHAT WE ARE BUILDING
--------------------------------------------------------------------------
An AI support assistant that:
  - answers customer questions using ONLY the business's approved information
  - sorts incoming issues into categories and suggests a priority
  - hands complicated or sensitive cases over to a human
  - shows the business simple numbers about its support (analytics)

Problem it solves:
Support teams keep answering the same questions again and again and need a
reliable way to organize and prioritize customer requests.

Who it is for (target users):
  - E-commerce stores
  - Service businesses
  - SaaS companies
  - Online businesses

IMPORTANT: Before building too much, we speak to 3-5 real small business
owners and check that this problem is real for them. Nothing here is a
guarantee of demand or revenue.

--------------------------------------------------------------------------
2. MVP FEATURES (first version only)
--------------------------------------------------------------------------
 1. Business knowledge-base setup (business adds FAQs, policies, documents)
 2. Customer question interface (chat screen)
 3. RAG-based answers grounded in the business's own information, with source shown
 4. Ticket categorization and priority suggestions
 5. Conversation history
 6. Human handoff when the AI is unsure or the topic is sensitive
 7. Basic support analytics (number of chats, handoffs, categories)

NOT in the MVP (later phase): WhatsApp / email / helpdesk integrations,
payments, multi-language, mobile app.

--------------------------------------------------------------------------
3. TECHNOLOGY STACK
--------------------------------------------------------------------------
  Backend:     Python + FastAPI
  Frontend:    React
  Database:    PostgreSQL (with vector search for embeddings)
  AI:          LLM API + RAG (embeddings, retrieval)
  Automation:  n8n (for selected automations, e.g. notifications)
  Later phase: Messaging / helpdesk integrations
  Tools:       Git + GitHub, Visual Studio Code

Main challenges we must handle:
  - Avoid wrong answers (AI must say "I'm not sure" and hand off instead of guessing)
  - Protect customer information
  - Make sure a human can take over at any time
  - Keep one business's data completely separate from another's

6. HOW WE WORK TOGETHER IN GIT AND GITHUB
--------------------------------------------------------------------------
Branches:
  main                 - stable version, only tested work
  dev                  - shared branch where our work meets
  feature/<name>       - a feature being built
  fix/<name>           - a bug fix
  Examples: feature/nazim-rag-pipeline, feature/zahid-chat-ui, fix/document-upload

Rules:
  1. Never work directly on main.
  2. Start every task from the latest dev.
  3. Small commits with clear messages.
  4. Push your feature branch to GitHub.
  5. Open a Pull Request into dev.
  6. The OTHER person reviews it.
  7. Run tests before merging.
  8. Merge only after review and passing checks.
  9. Pull latest dev before starting the next task.
 10. NEVER commit .env files, API keys, passwords or private customer data.

Daily routine:
    git checkout dev
    git pull origin dev
    git checkout -b feature/your-feature-name
    (work, then)
    git add .
    git commit -m "Short clear message"
    git push -u origin feature/your-feature-name
    -> open Pull Request on GitHub into dev

Task board: use GitHub Projects with columns To Do / In Progress / In Review / Done.
Every task in section 5 becomes one GitHub Issue assigned to its owner.
